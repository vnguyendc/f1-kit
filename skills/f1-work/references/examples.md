# Routing and continuation examples

These are illustrative requests and decisions, not bundled project integrations or evidence that a task has run. Use the actual project's instructions and available skills.

## Mixed launch brief

Request: “Continue the service launch: update the page, finish the carousel, and prepare the email.”

Find the existing launch brief and requested assets. Share confirmed service facts and CTA across them. Route repository changes through F1 at the current approval stage, and use available editorial/design/outreach skills for the other outputs. A new page-wide CTA change may need an amended development plan while independent authorized copy work continues. Do not add paid ads or send the email unless requested and authorized.

## Approved feature on another host

Request: “Pick up issue EXAMPLE-42 on this machine.”

Read that issue's plan and actual approval, then resolve this host's repository and worktree. Compare current candidate identity with the recorded checks; resume at the real stage and rerun affected checks. A packet's local temporary screenshot may be inaccessible here. Record that limitation or perform an authorized transfer instead of claiming the screenshot was reviewed. Do not create a duplicate issue or request unchanged, verifiable plan approval again.

## Content-only revision

Request: “Shorten the introduction in this draft.”

Read the supplied current draft, apply the relevant editorial guidance, and return the revision or perform the explicitly requested save. No application change, development plan, new session, or coordination record is required. If the request instead changes a repository-backed page, follow the project's development instructions.

## Conflicting matches or unavailable capability

Request: “Resume the newsletter.” Two existing projects have current newsletters.

Use supplied identifiers and context to narrow the matches. If the intended target remains ambiguous, present the concrete choice and continue only independent work. Do not silently combine them or create another project. If the requested platform or specialist is unavailable, say which operation cannot be verified; an available drafting capability can still produce a clearly labeled draft within scope.
