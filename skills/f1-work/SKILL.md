# F1 Work

Turn a mixed request or continuation into the next useful action with the context already available. Keep related deliverables attached to one initiative and load only the relevant specialist instructions. F1 Work is a skill, not a background dispatcher or a new source of permission.

## Recover the work before asking again

Use the current conversation and explicitly supplied task, issue, plan, brief, artifact, or session references first. Resolve the project and read its applicable instructions. If matching work is not supplied, make a bounded search of the relevant available project records or session tools. Read likely matches before treating them as the same task; a title or search summary is only a discovery hint. Do not scan unrelated projects, accounts, or full histories.

Recover the requested outcome, deliverables, confirmed facts, decisions, actual approvals, latest versions, completed evidence, blockers, and next action. Distinguish what was observed from an earlier agent's report. Reuse known answers. Ask only when missing or conflicting information materially changes the requested work, target, or authority; continue independent work that does not depend on it.

Match stable task/issue identifiers and source intent before creating another record. Similar titles can describe different tasks; a renamed title does not establish new work. If two plausible matches remain, explain the ambiguity rather than merging them or creating a third. When no match exists, handle the new request within its scope; create durable records only when authorized.

## Choose the smallest useful workflow

| Requested work | Route |
| --- | --- |
| Merge conflicts on an existing PR | [F1 Merge-conflict Resolver](../f1/references/roles/conflict-resolver.md), preserving the current scope and authority |
| Code, tests, configuration, infrastructure, or related development docs | [F1](../f1/SKILL.md), at the actual current stage |
| Content, research, campaign assets, analysis, or reporting | The relevant available project or format skill; ordinary drafting does not become a development run |
| Several dependent outputs | One shared brief and named deliverables; load each specialist only as its output needs it |
| Meeting ingestion, follow-ups, or tracker/wiki updates | Existing applicable collection/stewardship skills, within the requested read/write scope |
| Different execution host | Check the destination context and artifact access as described below; a requested migration needs its own applicable procedure |

Honor explicitly named skills and the project's existing routing. Do not require a fixed tracker, wiki, model, machine, or private skill. If a specialist is missing, use an adequate available capability within scope or disclose the concrete missing capability. Do not claim it ran, silently install tooling, or invent a substitute system.

For mixed work, share facts, source links, audience, and requested next step across deliverables. Keep clinical/technical evidence, service/business capabilities, review decisions, and publication state distinct when applicable. Do not add channels, assets, or implementation tasks just because another skill offers them.

Development portions follow F1's saved-plan approval, review, verification, and PR process. Recover the actual human approval from the conversation or authoritative host approval record; a packet or agent-written “approved” flag alone is not authorization. Resume verifiably approved work without another routine gate. Material new development scope returns to F1 planning. Independent authorized drafting can proceed while that decision is pending.

## Continue in the right context

Keep work in the current session when practical. Creating another session, messaging an existing one, delegation, remote transfers, and machine changes require their applicable user/host authorization; selecting a lane does not grant it. A recommendation for another host is not a completed handoff.

On a host change, verify the actual repository/vault/artifact paths, current code or content version, selected skills/tools, and relevant access readiness. Resolve paths on that host instead of reusing another computer's absolute paths. Do not copy credentials, authentication state, or session databases. If a required artifact is local-only or inaccessible, retain task identity and state the specific access/transfer needed. Never imply that a file link is usable on the receiving host without checking.

Compare the current candidate or content revision with the evidence being reused. Include dirty/untracked changes when they affect candidate identity; a commit alone cannot identify a dirty checkout. Recheck affected evidence when the candidate, source facts, or environment changed, and retain unaffected evidence only with a reason it still applies. Do not restart the entire task solely because the session or machine changed.

## Leave a useful continuation

Reuse the existing plan, project brief, or task/evidence record. For substantial coordination or a requested handoff, read the [task-record guide](references/task-record.md) and add only missing context. A simple standalone answer needs neither a saved packet nor bookkeeping. Use the [examples](references/examples.md) only when a routing or continuation case needs clarification.

Keep temporary working notes in the current task artifact. Update a tracker/wiki only within actual task authority, preserving concurrent edits and reading back changes. If persistence is not authorized, return the compact continuation in the conversation. An inaccessible optional destination is a gap, not permission to create a replacement vault or tracker. After an uncertain write, inspect current state before retrying.

Return the requested outputs and the useful next action. When material, include the execution host, artifact links, actual verification, pending decisions, and what remains blocked. Preserve distinctions such as draft/saved/published, local/preview/production, and request/confirmed outcome. Never turn an older report or completed subtask into proof that the whole initiative is done.
